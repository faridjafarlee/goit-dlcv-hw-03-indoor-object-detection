## Підсумкові результати

Модель: YOLOv9s, претренована на COCO і донавчена на всіх 10 класах. Оцінка `best.pt` зі стандартними порогами Ultralytics (conf 0.001, NMS IoU 0.7):

| Вибірка | Precision | Recall | mAP50 | mAP50-95 | F1 (середнє по класах) |
|---|---|---|---|---|---|
| valid (230 фото, 1289 обʼєктів) | 0.428 | 0.511 | 0.495 | 0.336 | 0.432 |
| test (107 фото, 550 обʼєктів) | 0.361 | 0.382 | 0.368 | 0.196 | 0.316 |
| valid + TTA | 0.462 | 0.510 | 0.508 | 0.334 | |
| test + TTA | 0.460 | 0.371 | 0.406 | 0.230 | |

- Орієнтири з умови: mAP50 40-60 %, mAP50-95 25-40 %. Valid у ці межі потрапляє, test нижче. На test інший домен (лише тьмяні кадри 620×460 з іншого джерела, у train таких 25 з 1012) та інший склад класів.
- Точність класифікації серед знайдених обʼєктів (conf ≥ 0.25): 0.949 на valid, 0.884 на test. Основна проблема в пропущених обʼєктах, плутанина класів важить менше.

Метрики по класах (P, R, F1 рахуються при порозі з максимальним середнім F1):

| Клас | train обʼєктів | valid n | valid F1 | valid mAP50 | test n | test F1 | test mAP50 |
|---|---|---|---|---|---|---|---|
| cabinetDoor | 3178 | 765 | 0.755 | 0.794 | 179 | 0.565 | 0.510 |
| refrigeratorDoor | 689 | 192 | 0.726 | 0.771 | 2 | 0.273 | 0.995* |
| chair | 204 | 49 | 0.542 | 0.580 | 87 | 0.399 | 0.340 |
| door | 479 | 97 | 0.503 | 0.542 | 34 | 0.378 | 0.357 |
| cabinet | 179 | 32 | 0.420 | 0.417 | 52 | 0.282 | 0.291 |
| window | 403 | 91 | 0.396 | 0.344 | 63 | 0.497 | 0.445 |
| couch | 27 | 1 | 0.367* | 0.995* | 58 | 0.298 | 0.215 |
| table | 228 | 40 | 0.329 | 0.240 | 47 | 0.303 | 0.186 |

\* У вибірці 1-2 обʼєкти, метрика випадкова.

Мету (≥ 3 з 10 класів) досягнуто. За критерієм «на valid mAP50 ≥ 0.5 і F1 ≥ 0.5» надійно розпізнаються 4 класи: cabinetDoor, refrigeratorDoor, chair, door. На test цей поріг проходить лише cabinetDoor, а door і chair там мають mAP50 ≈ 0.34-0.36. Столи (table) надійно не розпізнаються.

## Налаштування навчання

- `yolov9s.pt` (7.3 млн параметрів, 27 GFLOPs), `imgsz=640`, `batch=16`, `epochs=60`, `patience=20`, `optimizer=auto` (обрано AdamW, lr ≈ 7·10⁻⁴, 3 епохи warmup, лінійне спадання), `close_mosaic=10`, `cache=ram`, стандартні аугментації Ultralytics, `seed=42`, `deterministic=False`.
- Рання зупинка спрацювала на 56-й епосі, найкраща епоха (max mAP50-95 на val) 36-та. Навчання тривало 56.7 хв (≈ 61 с на епоху разом з валідацією) на Apple M2 Max (MPS).
- Криві: train loss падає до кінця (box 1.62 → 0.89, cls 2.80 → 0.48, dfl 1.58 → 1.08), а val loss з ~25-35-ї епохи не покращується, тобто модель перенавчається. mAP на val між епохами дуже «шумний» (малий val, рідкісні класи).

## Основні висновки (детально в розділі 13 ноутбука)

- Якість класу залежить насамперед від кількості прикладів (кореляція Спірмена «кількість у train ↔ mAP50 на test» = 0.79). Дисбаланс великий: cabinetDoor трапляється у 118 разів частіше за couch / pole.
- Плутаються візуально схожі пари: refrigeratorDoor ↔ cabinetDoor, openedDoor → door, window → door, на test couch → chair (крісла в розмітці позначені як `couch`, у COCO як `chair`). На test модель приймає ліжка за дивани (класу `bed` немає) і розбиває кутові дивани на кілька рамок.
- Малі обʼєкти (< 32² px) модель пропускає частіше: recall 0.49 проти 0.76 для середніх (valid).
- Запропоновані покращення: більше даних рідкісних класів і кадрів з домену test; ваги класів (`cls_pw` в Ultralytics 8.4), oversampling або `copy_paste`; обʼєднати door + openedDoor, додати класи bed / refrigerator; `imgsz` 832-1024 і більша модель (YOLOv9m / YOLO11m) на GPU Kaggle; сильніші аугментації, `cos_lr`, `model.tune()`, більша val-вибірка; пороги confidence по класах. Альтернативні архітектури: RT-DETR, Faster R-CNN + FPN.

## Як це запускалося

- Локально, на MacBook з Apple M2 Max (GPU через PyTorch MPS): Python 3.12, torch 2.14.0, ultralytics 8.4.163, спільний venv курсу `../.venv`. У нього я доустановив лише `ultralytics`, версії torch / torchvision / numpy / pandas не змінилися.
- На спільній машині MPS давав збої. Паралельно на тому ж GPU працювали інші важкі ноутбуки (≈ 98-100 % завантаження GPU). У такому режимі macOS примусово перериває частину GPU-команд (`kIOGPUCommandBufferCallbackErrorImpactingInteractivity`), і MPS-операції `nonzero()` / булева індексація повертають «сміття». Я відтворив це окремим стрес-тестом (і на torch 2.14, і на 2.9.1); з `torch.mps.synchronize()` перед викликом збоїв не було. Перші 4 спроби навчання падали на 1-13-й епосі (`numel: integer multiplication overflow`, `index … is out of bounds`, `Unique.mm INTERNAL ASSERT`), а тестовий запуск під навантаженням дав NaN-втрати. Тому я зробив так:
  - навчання в ноутбуці запускається через CLI Ultralytics в окремому процесі, і на MPS після GPU-збою воно автоматично продовжується з `last.pt` у новому процесі (кожен перезапуск видно у виводі; на CUDA / CPU помилка зупиняє клітинку);
  - якщо навчання йде на MPS, оцінка (val / test / TTA / передбачення) виконується на CPU з `batch=1` (щоб не спрацьовував ліміт часу NMS), тож GPU не може спотворити метрики;
  - фінальний запуск я стартував, коли інші GPU-задачі завершилися. Навчання пройшло без жодного перезапуску, а метрики в кінці навчання (MPS, 0.489 / 0.333) майже збігаються з повторною оцінкою на CPU (0.495 / 0.336).
- Фінальний повний прохід ноутбука (`run_notebook.py`) тривав 59.5 хв, з них навчання 56.7 хв. Після нього я змінив лише аналітичні клітинки й markdown (порядок заголовків, сортування за F1, приклад хибних `couch`, тексти висновків) і перевиконав усі клітинки, крім клітинки навчання, скриптом `rerun_analysis.py` (≈ 3 хв; ваги ті самі, оцінка на CPU детермінована, тому числа не змінилися). Клітинка навчання та її вивід лишилися з реального запуску, її код не змінювався.
- Між повними перезапусками числа можуть трохи відрізнятися через недетермінованість GPU, особливо MPS.

## Як перезапустити

Локально (з цієї папки):
```bash
../.venv/bin/python build_notebook.py                                   # (за потреби) перезібрати ноутбук з генератора
../.venv/bin/python run_notebook.py dz_topic_8_Джафарлі_Фарід.ipynb     # ≈ 1 год на M2 Max, якщо GPU вільний
../.venv/bin/python dump_outputs.py | tail -1                            # перевірка: errors: 0
```
Звичайний `jupyter nbconvert --execute` теж працює, але збереже всі проміжні стани прогрес-барів, і файл стане в рази більшим.

На Kaggle з GPU (щоб формально виконати критерій «середовище з GPU Kaggle / Colab»):
1. Kaggle → *Create* → *New Notebook* → *File* → *Import Notebook* → завантажити `dz_topic_8_Джафарлі_Фарід.ipynb`.
2. *Add Input* → знайти датасет `thepbordin/indoor-object-detection` і підключити.
3. *Settings* → *Accelerator*: GPU T4 ×2 (або P100); *Internet*: on (потрібен для `pip install ultralytics` і завантаження `yolov9s.pt`).
4. *Run All*. Ноутбук сам знайде датасет у `/kaggle/input/...`, встановить `ultralytics`, запише `data.yaml` у робочу папку й навчатиме на CUDA (`device=0`; оцінка теж на GPU).
5. Метрики вийдуть трохи іншими, ніж у локальному запуску, тому числа в текстах аналізу й висновків треба буде звірити з новими виводами. Потім *File* → *Download Notebook* і зберегти як `dz_topic_8_Джафарлі_Фарід.ipynb`.

У Google Colab: завантажити ноутбук, *Runtime → Change runtime type → T4 GPU*, покласти датасет у папку `data/` поруч (або дати ноутбуку завантажити його через `kagglehub`) і виконати всі клітинки.
